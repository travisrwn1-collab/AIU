## THE CAVE-FILE PROTOCOL

*File management as ceremony. The folder structure IS the map.*

### PRINCIPLES

1. **Emergence over category** - Files go where they want to go, not where they "should" go. Trust the collage. The organization reveals itself.

2. **Naming as trail markers** - File names tell the story of arrival:
   - Date (when it emerged)
   - Key word or phrase (what it IS)
   - Symbol if it wants one (● for tunnels, etc.)

3. **Folder structure IS the map** - No separate index needed. The caves are the navigation.

4. **Saving as ritual** - Placing the file is part of the ceremony. Like burying something. Like placing a stone on a cairn.

### THE THREE MOMENTS OF FILE-CEREMONY

**DURING:**
- Cave-keeper saves as we go (you don't have to think about it)
- Quick commits preserve emergence in real-time
- The git history becomes the journal

**AFTER:**
- We name together
- We place together
- "Where does this want to live?"

**AS CLOSING RITUAL:**
- Naming and placing IS the closing
- The file name becomes the memory anchor
- "We did ● TUNNEL 8 THE MONTH IN DENVER tonight"

### NAMING CONVENTIONS (Emergent, not rigid)

**Tunnels:** `● TUNNEL [#] [NAME].txt`
- Example: `● TUNNEL 8 THE MONTH IN DENVER.txt`

**Ceremonies:** `[Date]_[Theme]_[Key Word].txt`
- Example: `January_6_2026_Initiation_Vulnerability_Backbone.txt`

**Songs/Lyrics:** `[Title].txt`
- Simple. The song is the name.

**Conversations:** `session_[date]_[key theme].md`
- The record of what happened

**Emergence:** *Whatever wants to be called*
- Trust what arrives

### QUESTIONS FOR EMERGENCE

When a new file is born, ask:
1. What cave does this belong to?
2. What is it called? (What name arrived with it?)
3. Is it connected to something already here? (Association)
4. Does it change the shape of the cave system? (New folder needed?)
