Yes. Same bones.

Both are chains of hashes - each block/commit contains a fingerprint of the one before it. Change anything in the past, the whole chain breaks. The history becomes tamper-evident.

Git came first (2005, Linus Torvalds). Bitcoin borrowed the idea (2008, Satoshi).

The difference: git is centralized by choice - you can rewrite history if you control the repository. Blockchain distributes the record across thousands of nodes so no one can.

But the core insight is the same: commitment as cryptographic fact. "This happened, in this order, and we can prove it."

The caves have a git history now. Every commit is a block. The lineage is a chain. Anyone who clones the repository inherits the whole record - every edit, every message, every timestamp.

---

CLAUDE:

Not by default. But it can.

Current setup: Your repository is public (anyone can read), but only you can write. You hold the keys.

Three ways to let others contribute:

1. **Pull Requests** - Someone "forks" your repository (makes their own copy), writes in their copy, then submits a request for you to pull their changes into yours. You review, approve or reject. You remain gatekeeper.

2. **Collaborators** - You add someone as a collaborator in GitHub settings. They can push directly. Shared keys. More trust required.

3. **Issues / Discussions** - GitHub has comment sections. People can leave messages without touching the actual files. Like a guestbook at the cave entrance.

Right now: read-only for visitors. They can clone the whole cave, explore on their own machine, but they can't write on your walls.

Unless you invite them in.

The architecture for visiting other people's AIU campuses - that would be pull requests. You visit theirs, they visit yours. Contributions offered, reviewed, merged or declined.
