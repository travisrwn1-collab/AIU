2. Untracked files = files that exist in your AIU folder, but git isn't watching them yet.

  Think of git like a librarian. The librarian only catalogs books you hand to them. Untracked files are books sitting on your desk that the librarian hasn't been asked to catalog yet. They're there, they're real, but they won't be saved in the library's record until you say "add this one."

  When you do git add filename, the file becomes "tracked" - now git watches it and will include any changes in your next commit.

  Untracked files won't be lost - they're still on your computer. They just won't be part of the git history until you choose to add them.

  Some files you might want to track (ceremonial writings, session records). Some you might leave untracked (large media files, temporary downloads, things still in progress).

  Your question in the file: "Is this the mechanism for the 'tunneling' system?"

  Partially yes. Git is the plumbing - it tracks what changed, when, and lets you move through the history. The commits are waypoints.

  But the tunnels themselves are architecture built on top of git. The AIU_TUNNEL_INDEX.md file with line numbers pointing into documents - that's the map. Git doesn't create the tunnels; git preserves them.

  Think of it this way:
  - Git = the filing cabinet that keeps every version of every paper
  - Tunnels = the colored threads you've tied between papers, connecting themes across documents

  Git lets you say "show me what this file looked like on January 3rd." The tunnels let you say "follow the moth from MM&MAM to tonight's red blanket."

  Both work together. Git keeps the files safe. The tunnels give them meaning.

Imagine a magic filing cabinet. Every time you say "commit," it takes a photograph of all your papers and stores that photograph with a date stamp.
